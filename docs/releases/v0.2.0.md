## Changes

- Complete dev Online Shop: ten application services, Redis and a separately trusted Collector.
- Immutable source/digest contracts, independent verification, protected candidate evidence,
  separate signing, Binary Authorization and protected Cloud Deploy rendering/preflight.
- Isolated Terraform execution roots with explicit state ownership and cloud/Kubernetes stages.
- Protected HTTPS using DNS, Certificate Manager, Gateway API, external Application Load
  Balancer and Cloud Armor; deployment-only endpoint selection reuses trusted artifacts.
- Component/release-attributed traces, metrics and native-linked logs; six PromQL dashboard
  queries; HTTPS and bounded synthetic monitoring, alerting and guarded incident recovery.
- Permanent workload-pool placement and recorded repeat manual stop/resume acceptance.

## Recorded validation

The [acceptance record and checklist](../online-shop-acceptance.md) bind the deployed release,
producing source and observations. The protected45-resource rollout, exact-digest runtime,
one14-request checkout with exact Redis cleanup, ten-service signals and six dashboard queries
passed their bounded recorded checks. The recommendation deadline fix passed seven recorded
server calls and their downstream catalog calls, not a sustained/load scenario.

WAF SQLi/XSS403 and normal HTTPS200 were attributed to actual enforced policy logs.
The [incident exercise](../../monitoring/online-shop/incident-acceptance.md) confirmed detection,
operator-received failure email, bounded recovery, successful scheduled results and incident
closure. Exact email receipt time is unknown. Repeated stop/resume recovered permanent
placement and Collector2/2 without ad hoc eviction. These records are not current health:
nodes remain paused and no new live validation accompanies these notes.

## Accepted limitations

1. **429 verification deferred:** neither the temporary throttle-denial mechanism nor the
   actual1200/60s/IP threshold has a confirmed429 in this environment. Scoped1500 failed its
   match/readiness check; all temporary rules were removed. The mismatch cause is unresolved.
2. **Historical PromQL NO_DATA:** retained constant cumulative counter samples cannot recreate
   the original positive alert evaluation. An empty filtered vector is not zero errors or a
   passed query. Actual incident, raw counter and trace/log evidence remain independent proof.
   See the [analysis](../../monitoring/online-shop/promql-incident-limit.md).

Redis and Collector buffers are ephemeral. Capacity, sustained reliability, export losslessness,
HA, production hardening, canary, environment progression and executed release rollback are not
claimed. Sample-service is retired. Platformv0.2.0 identifies implementation/contracts, not an
application image version or an automatic rebuild/deployment.
